# NFTs (NEP-171)

**NEP-171** is NEAR's non-fungible token standard. It is usually paired with:

- **NEP-177** metadata: `nft_metadata()` for the collection and `TokenMetadata` (title, description, media, `issued_at`, `extra`) for each token.
- **NEP-181** enumeration: `nft_tokens`, `nft_total_supply`, `nft_tokens_for_owner`.
- **NEP-297** events: contracts log `EVENT_JSON:` lines such as `nft_mint`, so explorers and indexers can follow them.

## NFTs as credentials

The Retr0school diploma is an NFT, but it is not a collectible. It is a **credential**, so the contract makes three choices:

1. **One per account per track.** The token id is `near:your-account.testnet`, so a second mint fails.
2. **Graded on chain.** You send your quiz answers to `mint_diploma`; the contract scores them and only mints if you pass.
3. **Soulbound.** `nft_transfer` always panics. A diploma you could sell would prove nothing.

```rust
fn nft_transfer(&mut self, receiver_id: AccountId, token_id: TokenId,
                approval_id: Option<u64>, memo: Option<String>) {
    env::panic_str("Diplomas are soulbound and cannot be transferred");
}
```

The diploma's `extra` field stores JSON: track, score, max score, owner, and date. Anyone can check it with the `verify_diploma` view method or on the [verify page](/verify).
