# Wallets, Keys, and Staying Safe

In Web3, you do not have a username and password stored by a company. You have a **key pair**, and a **wallet** is the app that manages it.

<Anim name="access-keys" caption="One NEAR account can hold many keys with different permissions." />

## Public and private keys

- **Private key**: a secret, randomly generated 256-bit number. It proves you own your account and lets you sign transactions. **Whoever has it controls your funds.**
- **Public key**: mathematically derived from the private key. It is safe to share.
- **Account**: on NEAR you share a readable **account id** like `alice.testnet`. The account stores which public keys may act for it. (An *implicit* account is simply the 64-hex form of a public key, before you give it a name.)

The math works one way: it is easy to go from private key to public key, but practically impossible to go back. NEAR uses **ed25519** keys, written as `ed25519:` plus base58.

```bash
Private key  ──►  Public key (ed25519:…)  ──►  added to account  alice.testnet
  (secret)          (public)                    (share freely)
```

<Note>
A wallet does not actually "hold" your coins. Your assets are recorded on the blockchain. The wallet holds the **keys** that let you move them.
</Note>

## Seed phrases

Most wallets generate a **seed phrase** (also called a recovery or secret recovery phrase): 12 or 24 ordinary words, like `ocean ladder spoon ...`. These words can regenerate all of your private keys. If you lose your device, the seed phrase restores your wallet anywhere.

<Warning>
**Your seed phrase is the master key to everything in your wallet.**

- Never type it into a website, form, chat, or email.
- Never share it with anyone, including "support staff". Real support will never ask for it.
- Never store it in a screenshot, cloud note, or password-less file.
- Write it on paper (or metal) and keep it somewhere safe and private.

If someone gets your seed phrase, they can take everything, and blockchain transactions cannot be reversed.
</Warning>

## Types of wallets

| Type | Examples | Pros | Cons |
| --- | --- | --- | --- |
| Web wallet | MyNearWallet | Nothing to install, works on testnet | Keys live in that site's browser storage |
| Browser extension | Meteor, Sender | Easy to use with dApps | Lives on an internet-connected computer |
| Mobile / Telegram | HOT Wallet, Meteor mobile | Convenient, QR codes | Phone loss or malware risk |
| Hardware | Ledger (NEAR app) | Keys never leave the device | Costs money, less convenient |
| Custodial | Exchange accounts | Password reset possible | The company holds your keys ("not your keys, not your coins") |
| Multisig / DAO | Sputnik DAO, multisig contracts | Several approvals, recovery options | More complex setup |

<Tip>
A common setup: a hardware wallet for long-term savings, and a separate "hot" wallet with small amounts for trying new apps.
</Tip>

## Signing

When you send a transaction or log in to a dApp, your wallet asks you to **sign** a message with your private key. The signature proves you approved it, without revealing the key.

There are two kinds of requests:

- **Transaction signing**: changes something on-chain (sends tokens, calls a contract). Costs gas.
- **Message signing**: proves you own an account without a transaction. On NEAR this is **NEP-413** `signMessage`. It is free. Retr0 Academy uses it to unlock Advanced NEAR for certificate holders.

<Note>
NEAR accounts can hold many **access keys**: *full-access* keys can do anything, while *function-call* keys can only call chosen methods on one contract and cannot move NEAR. dApps usually ask for a function-call key, so they can act without asking you to approve every click.
</Note>

<Warning>
Read every signature request carefully. Some malicious sites ask you to sign an **approval** that lets them spend your tokens, or a signed message that authorizes a transfer. If you do not understand what you are signing, **reject it**.
</Warning>

## Safety checklist

- Bookmark the real sites you use and only connect through those bookmarks. Scam sites copy real ones and use look-alike domain names.
- Ignore unexpected direct messages offering help, airdrops, or prizes.
- Use **NEAR testnet** while learning: create a free `…testnet` account in MyNearWallet or Meteor, and top it up from the [testnet faucet](https://near-faucet.io). Test NEAR has no value, so mistakes cost nothing.
- Review your account's access keys now and then (in your wallet or on NearBlocks) and delete keys for apps you no longer use.
- Keep your wallet app and browser updated.
- If an offer sounds too good to be true, it is.

## Try it: is this a valid NEAR account id?

NEAR account ids are 2 to 64 characters of lowercase letters, digits, and `-` or `_` separators, split into parts by dots, like `alice.testnet` or `app.alice.near`. A 64-character hex string is an *implicit* account. This checker validates the **format** only. It does not prove the account exists.

input { padding: 8px; font-family: monospace; }
.ok { color: #16a34a; }
.bad { color: #dc2626; }
.hint { color: #6b7280; font-size: 0.85rem; }`} js={`const input = document.getElementById("acct");
const result = document.getElementById("result");
const PART = /^(?:[a-z\\d]+[-_])*[a-z\\d]+$/;

function kind(id) {
  if (id.length < 2 || id.length > 64) return null;
  if (/^[0-9a-f]{64}$/.test(id)) return "implicit account (a public key in hex)";
  if (!id.split(".").every((part) => PART.test(part))) return null;
  if (id.endsWith(".testnet")) return "named testnet account";
  if (id.endsWith(".near")) return "named mainnet account";
  return "valid format (top-level or other suffix)";
}

function check() {
  const id = input.value.trim();
  const k = kind(id);
  result.className = k ? "ok" : "bad";
  result.textContent = k ? "✅ " + k : "❌ Not a valid NEAR account id (lowercase, 2-64 chars, no empty parts).";
}

input.addEventListener("input", check);
check();`} />

<Tip>
Account ids are case-sensitive and must be lowercase, so `Alice.testnet` is not the same as `alice.testnet`: it is invalid. Still, always double-check the whole id before sending NEAR.
</Tip>

## Summary

- Your private key (and the seed phrase that generates it) controls your assets. Never share it.
- Your account id is public and safe to share for receiving NEAR.
- Wallets manage keys and sign transactions and messages.
- Read every signature request, use testnets while learning, and beware of scams.
