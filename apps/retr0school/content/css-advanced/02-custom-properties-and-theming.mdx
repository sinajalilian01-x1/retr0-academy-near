# Custom Properties and Theming

Custom properties (CSS variables) are properties you invent, prefixed with `--`. Unlike preprocessor variables, they are **live**: they inherit through the DOM, react to media queries and can be changed at runtime by JavaScript. This site's whole retro theme is a set of them.

```css
:root {
  --color-bg: #fff7e6;
  --color-ink: #1a1530;
  --color-accent: #ff3fa4;
  --space: 8px;
}
.button {
  background: var(--color-accent);
  padding: calc(var(--space) * 1.5) calc(var(--space) * 3);
}
```

## Fallbacks and scope

```css
color: var(--brand, hotpink);   /* fallback if --brand is not defined */
.card { --pad: 24px; }          /* scoped: only .card and its children see this value */
.card.compact { --pad: 12px; }  /* override per variant */
```

## Design tokens: two layers

1. **Primitive tokens** describe raw values: `--pink-500: #ff3fa4`.
2. **Semantic tokens** describe purpose: `--accent: var(--pink-500)`.

Components only use semantic tokens. A theme is then just a different mapping.

Moving the slider changes **one** variable; every component that uses `--accent` updates instantly.

## Reading and writing from JavaScript

```js
const root = document.documentElement;
getComputedStyle(root).getPropertyValue("--hue"); // " 328"
root.style.setProperty("--hue", "190");
```

<Tip>
Typed custom properties with `@property --angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }` can even be animated, because the browser knows how to interpolate them.
</Tip>

## Summary

Define primitive and semantic tokens on `:root`, override them per theme or per component, honour `prefers-color-scheme`, and update variables from JavaScript for live theming.
