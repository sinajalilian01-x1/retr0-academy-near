# Semantics and Accessibility

Browsers build two trees from your HTML: the DOM, and the **accessibility tree** that screen readers, voice control and switch devices use. Semantic elements put real meaning into that second tree for free. A `<div onclick>` gives it nothing.

<Anim name="landmarks" caption="Landmarks let screen reader users jump straight to the region they want." />

## Landmarks

Each landmark element maps to an ARIA role automatically:

| Element | Implicit role | Use it for |
| --- | --- | --- |
| `<header>` (top level) | `banner` | Site logo and title |
| `<nav>` | `navigation` | Main or section navigation |
| `<main>` | `main` | The one primary content area per page |
| `<aside>` | `complementary` | Related, skippable content |
| `<footer>` (top level) | `contentinfo` | Copyright, legal, contacts |
| `<section>` with a heading | `region` | A themed group with a name |

## Headings are an outline

Screen reader users often navigate by heading. Use one `<h1>`, then never skip levels on the way down (`h2` → `h3`, not `h2` → `h4`). Pick the level by **structure**, then style the size with CSS.

## Accessible names

Every interactive control needs a name the browser can announce:

```html
<!-- visible text is the name -->
<button>Mint diploma</button>

<!-- icon-only button: give it a name -->
<button aria-label="Close dialog"><svg aria-hidden="true">...</svg></button>

<!-- inputs get their name from a label -->
<label for="acct">NEAR account</label>
<input id="acct" name="acct">
```

<Warning>
The first rule of ARIA: if a native element does the job, use it. `<button>` already handles focus, Enter and Space, and the `button` role. A `div role="button"` needs all of that rebuilt by hand.
</Warning>

## Keyboard focus

Everything clickable must be reachable with Tab and visible when focused. Never remove outlines without a replacement:

<TryIt title="Accessible card list with visible focus" html={`<a class="skip" href="#main">Skip to content</a>
<header><strong>Retr0 Demo</strong></header>
<nav aria-label="Main">
  <a href="#">Courses</a> <a href="#">Playground</a>
</nav>
<main id="main">
  <h1>Courses</h1>
  <section aria-labelledby="near-h">
    <h2 id="near-h">NEAR</h2>
    <button aria-expanded="false" aria-controls="near-more" id="toggle">Show lessons</button>
    <ul id="near-more" hidden>
      <li>Accounts and keys</li>
      <li>Smart contracts</li>
    </ul>
  </section>
</main>`} css={`body { font-family: system-ui; background: #0d0b1a; color: #e8e6ff; padding: 1rem; }
a { color: #6ff6ff; }
button { font: inherit; padding: .5rem 1rem; background: #ff3fa4; border: 0; color: #0d0b1a; }
:focus-visible { outline: 3px solid #ffd84a; outline-offset: 3px; }
.skip { position: absolute; left: -999px; }
.skip:focus { left: 1rem; top: 1rem; background: #17132b; padding: .5rem; }`} js={`const btn = document.getElementById("toggle");
const list = document.getElementById("near-more");
btn.addEventListener("click", () => {
  const open = btn.getAttribute("aria-expanded") === "true";
  btn.setAttribute("aria-expanded", String(!open));
  list.hidden = open;
  btn.textContent = open ? "Show lessons" : "Hide lessons";
});`} />

Press Tab inside the preview: the hidden "Skip to content" link appears first, then focus moves with a clear yellow ring. `aria-expanded` tells assistive tech whether the list is open.

## Images and alt text

- Informative image: describe what matters (`alt="Diploma NFT for alice.testnet, score 38/40"`).
- Decorative image: empty alt (`alt=""`) so it is skipped.
- Never write "image of"; the screen reader already says it is an image.

## Checklist

1. Landmarks: one `main`, labelled `nav` elements.
2. Headings in order.
3. Every control has a name; icon buttons use `aria-label`.
4. Visible `:focus-visible` styles.
5. Color contrast of at least 4.5:1 for body text.

## Summary

Semantic HTML is the cheapest accessibility work you will ever do. Reach for native elements first, add ARIA only to describe state (`aria-expanded`, `aria-current`) or to name things, and test with the keyboard.
