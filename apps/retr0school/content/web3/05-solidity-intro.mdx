# Introduction to Solidity

**Solidity** is the most popular language for writing smart contracts on Ethereum and other EVM chains. Its syntax looks a bit like JavaScript, but it is **statically typed** and compiled.

## Your first contract

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract HelloWeb3 {
    string public greeting = "Hello, Web3!";

    function setGreeting(string memory newGreeting) public {
        greeting = newGreeting;
    }
}
```

Line by line:

- `SPDX-License-Identifier`: states the code's license (the compiler warns without it).
- `pragma solidity ^0.8.20;`: which compiler versions this code works with (0.8.20 or newer, below 0.9.0).
- `contract HelloWeb3`: like a class. Everything inside belongs to the contract.
- `string public greeting`: a **state variable**, stored permanently on the blockchain. `public` automatically creates a free getter function `greeting()`.
- `setGreeting`: a function that changes state, so calling it requires a transaction and gas.
- `memory`: tells Solidity the argument is temporary data that exists only during the call.

## Common types

| Type | Example | Notes |
| --- | --- | --- |
| `bool` | `true` | |
| `uint256` | `42` | Unsigned (non-negative) integer, 256 bits. `uint` is an alias. |
| `int256` | `-7` | Signed integer |
| `address` | `0x71C7...976F` | An account or contract address |
| `string` | `"hi"` | Text |
| `bytes32` | fixed 32 bytes | Often used for hashes |
| `mapping(address => uint256)` | | A key-value lookup table |
| `uint256[]` | | A dynamic array |
| `struct` | | A custom group of fields |

<Note>
Solidity has no decimals. Amounts are stored as whole numbers in the smallest unit. For ETH that unit is **wei**: 1 ETH = 10^18 wei.
</Note>

## Visibility and mutability

```solidity
function a() public { }         // callable by anyone, inside or outside
function b() external { }       // callable only from outside the contract
function c() internal { }       // this contract and contracts that inherit it
function d() private { }        // only this contract

function total() public view returns (uint256) { }  // reads state, no changes
function add(uint256 x, uint256 y) public pure returns (uint256) {
    return x + y;                                    // no state read or write
}
function donate() public payable { }                 // can receive ETH
```

## Special global variables

- `msg.sender`: the address calling the function right now.
- `msg.value`: how much ETH (in wei) was sent with the call.
- `block.timestamp`: the current block's time (seconds since 1970).
- `address(this).balance`: the contract's ETH balance.

## A complete example: a tip jar

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract TipJar {
    address public owner;
    mapping(address => uint256) public tipsFrom;

    event Tipped(address indexed from, uint256 amount, string message);

    constructor() {
        owner = msg.sender; // whoever deploys the contract becomes the owner
    }

    modifier onlyOwner() {
        require(msg.sender == owner, "Not the owner");
        _; // run the rest of the function here
    }

    function tip(string calldata message) external payable {
        require(msg.value > 0, "Send some ETH");
        tipsFrom[msg.sender] += msg.value;
        emit Tipped(msg.sender, msg.value, message);
    }

    function withdraw() external onlyOwner {
        uint256 amount = address(this).balance;
        (bool ok, ) = payable(owner).call{value: amount}("");
        require(ok, "Transfer failed");
    }
}
```

New ideas in this contract:

- **constructor**: runs once, at deployment.
- **mapping**: `tipsFrom[someAddress]` returns how much that address has tipped (0 by default).
- **require**: checks a condition; if it is false, the whole transaction **reverts** with the message.
- **modifier**: reusable checks you can attach to functions, like `onlyOwner`.
- **event** and **emit**: write a log that apps can listen to. Events are cheap and great for showing activity in a UI.
- **calldata**: read-only data passed into an external function. It is cheaper than `memory`.

<Warning>
Since Solidity 0.8, arithmetic **overflow** automatically reverts, which prevents a classic class of bugs. But many other bugs remain possible, such as reentrancy and broken access control. Follow the **checks-effects-interactions** pattern: validate first, update your state second, and call other contracts or send ETH last.
</Warning>

## Deploying with Remix (no installs needed)

1. Open **remix.ethereum.org** in your browser.
2. Create a file `TipJar.sol` and paste the contract.
3. Open the **Solidity compiler** tab and click **Compile**.
4. Open **Deploy & run transactions**. Choose the **Remix VM** environment for a free, simulated blockchain in your browser.
5. Click **Deploy**, then call `tip` (set a value first) and `withdraw` from the deployed contract panel.

<Tip>
Start in the Remix VM. When you are ready for a real network, use a **testnet** like Sepolia with free test ETH from a faucet. Only move to mainnet after testing thoroughly.
</Tip>

## Professional tools

For larger projects, developers use frameworks like **Hardhat** or **Foundry** for compiling, testing, and deploying:

```bash
# Foundry
forge init my-project
forge build
forge test
```

## Summary

- Solidity contracts have state variables, functions, a constructor, events, and modifiers.
- Types are explicit: `uint256`, `address`, `bool`, `string`, `mapping`, and more.
- `view` and `pure` functions do not change state; `payable` functions can receive ETH.
- `require` reverts on failure; `msg.sender` and `msg.value` describe the caller.
- Practice in Remix VM, then on a testnet, before ever using mainnet.
