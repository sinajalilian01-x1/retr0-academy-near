# Connecting a dApp with JavaScript

A **dApp** (decentralized application) is usually a normal website (HTML, CSS, JavaScript) that talks to smart contracts through the user's wallet. In this lesson you will connect a page to a wallet, read data, and send a transaction.

## The pieces

- **Wallet** (like MetaMask): holds the user's keys and asks them to approve actions.
- **Provider**: a connection to a blockchain node, used to **read** data.
- **Signer**: an account that can **sign** transactions, used to **write**.
- **Library**: **ethers.js** or **viem** wraps all of this in a friendly API.

## The window.ethereum object

Browser wallets inject an object called `window.ethereum` (defined by the EIP-1193 standard) into every page. You can check for it and request accounts:

```js
if (window.ethereum) {
  const accounts = await window.ethereum.request({ method: "eth_requestAccounts" });
  console.log("Connected:", accounts[0]);
} else {
  console.log("Please install a wallet such as MetaMask.");
}
```

<Note>
`eth_requestAccounts` opens the wallet's pop-up so the user can choose to connect. Your site never sees the private key; it only receives the public address.
</Note>

## Setting up ethers.js

Install it in a project:

```bash
npm install ethers
```

Or load it in a plain HTML page as a module:

```html
<script type="module">
  import { ethers } from "https://cdn.jsdelivr.net/npm/ethers@6/dist/ethers.min.js";
  // your code here
</script>
```

## Reading data

```js
import { ethers } from "ethers";

// Use the wallet's connection to the blockchain
const provider = new ethers.BrowserProvider(window.ethereum);

// Ask the user to connect and get a signer
const signer = await provider.getSigner();
const address = await signer.getAddress();

// Read the ETH balance (returned in wei, as a BigInt)
const balanceWei = await provider.getBalance(address);
console.log("Balance:", ethers.formatEther(balanceWei), "ETH");

// Which network are we on?
const network = await provider.getNetwork();
console.log("Chain ID:", network.chainId); // e.g. 11155111n for Sepolia
```

<Tip>
In ethers v6, big numbers come back as JavaScript **BigInt** values (notice the `n` suffix, like `11155111n`). Use `ethers.formatEther` and `ethers.formatUnits` to display them.
</Tip>

## Calling a smart contract

To talk to a contract you need its **address** and its **ABI**. ethers accepts a "human-readable" ABI, which is just the function signatures:

```js
const tokenAddress = "0xYourTokenContractAddress";
const abi = [
  "function name() view returns (string)",
  "function symbol() view returns (string)",
  "function decimals() view returns (uint8)",
  "function balanceOf(address owner) view returns (uint256)",
  "function transfer(address to, uint256 amount) returns (bool)",
  "event Transfer(address indexed from, address indexed to, uint256 value)",
];

// Read-only: connect the contract to the provider
const token = new ethers.Contract(tokenAddress, abi, provider);
const [symbol, decimals, raw] = await Promise.all([
  token.symbol(),
  token.decimals(),
  token.balanceOf(address),
]);
console.log(ethers.formatUnits(raw, decimals), symbol);
```

## Sending a transaction

Writing needs the **signer**. The wallet pops up so the user can review and approve:

```js
const tokenWithSigner = new ethers.Contract(tokenAddress, abi, signer);

try {
  const tx = await tokenWithSigner.transfer(
    "0xRecipientAddress",
    ethers.parseUnits("10", decimals) // 10 tokens
  );
  console.log("Sent! Hash:", tx.hash);

  const receipt = await tx.wait(); // wait until it is mined
  console.log("Confirmed in block", receipt.blockNumber);
} catch (error) {
  // e.g. the user clicked "Reject" in their wallet
  console.error("Transaction failed or was rejected:", error.shortMessage || error.message);
}
```

Sending plain ETH is similar:

```js
const tx = await signer.sendTransaction({
  to: "0xRecipientAddress",
  value: ethers.parseEther("0.01"),
});
await tx.wait();
```

## Listening for events and changes

```js
// React when the contract emits Transfer events
token.on("Transfer", (from, to, value) => {
  console.log(from, "→", to, ethers.formatUnits(value, decimals));
});

// React when the user switches accounts or networks in their wallet
window.ethereum.on("accountsChanged", (accounts) => console.log("Now using", accounts[0]));
window.ethereum.on("chainChanged", () => window.location.reload());
```

## Good dApp practices

- Show clear states: **not connected**, **connecting**, **wrong network**, **waiting for confirmation**, **confirmed**, **failed**.
- Check the chain ID and ask users to switch to the right network.
- Show the transaction hash with a link to a block explorer.
- Handle the user rejecting a request gracefully; it is not an error to panic about.
- Never ask for a seed phrase or private key. A dApp only ever needs the wallet to sign.

<Warning>
Develop and test on a **testnet** like Sepolia with free test ETH. Never hard-code a private key into front-end code; anything in the browser is visible to everyone.
</Warning>

<Tip>
Popular toolkits like **wagmi** with **RainbowKit** or **ConnectKit** add ready-made "Connect wallet" buttons, multi-wallet support, and React hooks on top of these same ideas.
</Tip>

## Summary

- Wallets inject `window.ethereum`; `eth_requestAccounts` asks the user to connect.
- A provider reads data; a signer signs transactions.
- ethers.js `Contract` objects call contract functions using an address and ABI.
- Writes return a transaction; `await tx.wait()` waits for confirmation.
- Handle rejections, wrong networks, and loading states, and test on a testnet first.
