# Tokens and ERC-20

A **token** is a digital asset managed by a smart contract. A **fungible** token is one where every unit is identical and interchangeable, just like one dollar is as good as another. Stablecoins (USDC, DAI), governance tokens, and reward points are usually fungible tokens.

## What is ERC-20?

**ERC-20** is a standard: a list of functions and events every fungible token contract agrees to implement. Because all ERC-20 tokens share the same interface, wallets, exchanges, and apps can support any of them automatically.

```solidity
interface IERC20 {
    function totalSupply() external view returns (uint256);
    function balanceOf(address account) external view returns (uint256);
    function transfer(address to, uint256 amount) external returns (bool);
    function allowance(address owner, address spender) external view returns (uint256);
    function approve(address spender, uint256 amount) external returns (bool);
    function transferFrom(address from, address to, uint256 amount) external returns (bool);

    event Transfer(address indexed from, address indexed to, uint256 value);
    event Approval(address indexed owner, address indexed spender, uint256 value);
}
```

Most tokens also include optional metadata functions: `name()`, `symbol()`, and `decimals()`.

| Function | What it does |
| --- | --- |
| `totalSupply()` | How many tokens exist |
| `balanceOf(addr)` | How many tokens an address holds |
| `transfer(to, amount)` | Send your tokens to someone |
| `approve(spender, amount)` | Allow another address (often a contract) to spend up to `amount` of your tokens |
| `allowance(owner, spender)` | How much the spender is still allowed to spend |
| `transferFrom(from, to, amount)` | The spender moves tokens on the owner's behalf |

## Decimals

Solidity has no decimal numbers, so tokens store balances as whole numbers and declare how many **decimals** to display. Most tokens use **18 decimals** (like ETH and wei). USDC uses 6.

```bash
Displayed balance: 1.5 TOKEN
Stored on-chain:   1500000000000000000   (1.5 × 10^18)
```

## Approve and transferFrom

Why two steps? A contract (like an exchange) cannot pull tokens from your wallet without permission. So you first **approve** it to spend a certain amount, then the contract calls **transferFrom** when you trade.

```bash
1. You  ──approve(DEX, 100)──►  Token contract
2. You  ──swap()──►  DEX  ──transferFrom(you, DEX, 100)──►  Token contract
```

<Warning>
Many apps ask for an **unlimited** approval for convenience. If that app's contract is hacked or malicious, it can take all of that token from your wallet. Approve only what you need when possible, and revoke approvals you no longer use.
</Warning>

## Create your own token

Writing a token from scratch is error-prone. Instead, developers inherit from **OpenZeppelin Contracts**, a widely used, audited library:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract SchoolCoin is ERC20, Ownable {
    constructor() ERC20("School Coin", "SCH") Ownable(msg.sender) {
        // Mint 1,000,000 tokens (with 18 decimals) to the deployer
        _mint(msg.sender, 1_000_000 * 10 ** decimals());
    }

    // Only the owner can create more tokens
    function mint(address to, uint256 amount) external onlyOwner {
        _mint(to, amount);
    }
}
```

That is all it takes. The parent `ERC20` contract provides `transfer`, `approve`, `balanceOf`, and the rest.

<Tip>
In Remix you can import OpenZeppelin directly with the same import path. Deploy `SchoolCoin` in the Remix VM, then call `balanceOf` with your address and `transfer` to another test account.
</Tip>

<Note>
Creating a token is easy. That is also why many scam tokens exist. A token having a name and a price chart tells you nothing about whether it is legitimate or has any value.
</Note>

## Summary

- Fungible tokens are interchangeable units, managed by a smart contract.
- ERC-20 defines `transfer`, `approve`, `transferFrom`, `balanceOf`, `allowance`, `totalSupply`, and `Transfer`/`Approval` events.
- Balances are stored as integers; `decimals` (often 18) says how to display them.
- Approvals let contracts spend your tokens; be careful with unlimited approvals.
- Use OpenZeppelin instead of writing token logic from scratch.
