# Smart Contracts

A **smart contract** is a program stored on the blockchain. Once deployed, it runs exactly as written, and anyone can interact with it by sending transactions.

Think of a vending machine: put in the right coins, press a button, and the machine follows its rules to give you a snack. No shopkeeper is needed. A smart contract is a digital vending machine for rules about money, ownership, and data.

## What can smart contracts do?

- **Tokens**: create currencies and points (ERC-20)
- **NFTs**: prove ownership of unique items (ERC-721)
- **Decentralized exchanges**: swap tokens without a company in the middle
- **Lending**: borrow and lend with automatic interest
- **DAOs**: groups that vote on decisions and share a treasury
- **Escrow and crowdfunding**: release funds only when conditions are met

## How they work

1. A developer writes the contract in a language like **Solidity**.
2. A compiler turns it into **bytecode** for the **EVM** (Ethereum Virtual Machine), the shared "computer" that every node runs.
3. The developer **deploys** the bytecode with a transaction. The contract gets its own **address**.
4. Users call the contract's functions by sending transactions (or free read-only calls).

```bash
Solidity source  ──compile──►  Bytecode + ABI  ──deploy──►  Contract at 0xABC...
```

## Accounts on Ethereum

| | Externally Owned Account (EOA) | Contract Account |
| --- | --- | --- |
| Controlled by | A private key (a person) | Its own code |
| Can start transactions? | Yes | No, only reacts when called |
| Has code? | No | Yes |
| Has a balance? | Yes | Yes |

## Reading vs. writing

- **Read** (view) functions just look at data. They are free when called from outside, and do not need a transaction.
- **Write** functions change the state. They need a signed transaction and cost gas.

## The ABI

The **ABI** (Application Binary Interface) is a JSON description of a contract's functions and events. Your JavaScript app uses it to know how to call the contract:

```json
[
  {
    "type": "function",
    "name": "balanceOf",
    "stateMutability": "view",
    "inputs": [{ "name": "account", "type": "address" }],
    "outputs": [{ "name": "", "type": "uint256" }]
  }
]
```

## Immutability: a superpower and a risk

Once deployed, a contract's code generally **cannot be changed**. That builds trust (the rules cannot be secretly altered), but it means bugs are permanent too.

<Warning>
Smart contract bugs have caused losses of billions of dollars. Real contracts that hold value should use well-tested libraries (like OpenZeppelin), have thorough tests, and get a professional **security audit** before launch. Never deploy experimental code to mainnet with real money.
</Warning>

<Note>
Some projects use **upgradeable proxy** patterns to allow changes. This adds flexibility but also means someone holds the power to change the rules, so users must trust them.
</Note>

## Oracles

Contracts can only see data that is on the blockchain. To use outside information (like the price of a stock or the weather), they rely on **oracles**, services such as Chainlink that bring off-chain data on-chain.

## Summary

- A smart contract is a program on the blockchain that runs exactly as written.
- Contracts are compiled to EVM bytecode and have their own address.
- Reading is free; writing needs a transaction and gas.
- The ABI describes how apps talk to a contract.
- Deployed code is usually permanent, so security matters enormously.
