# NFTs, ERC-721, and Metadata

An **NFT** (non-fungible token) is a token where every unit is **unique**. Each one has its own ID and owner. NFTs can represent digital art, event tickets, game items, memberships, certificates, or domain names.

| | Fungible (ERC-20) | Non-fungible (ERC-721) |
| --- | --- | --- |
| Units | Identical and divisible | Unique, each with a token ID |
| Example question | "How many do you have?" | "Which one do you own?" |
| Main lookup | `balanceOf(owner)` | `ownerOf(tokenId)` |

## The ERC-721 standard

Key functions every ERC-721 contract provides:

```solidity
function balanceOf(address owner) external view returns (uint256);
function ownerOf(uint256 tokenId) external view returns (address);
function safeTransferFrom(address from, address to, uint256 tokenId) external;
function transferFrom(address from, address to, uint256 tokenId) external;
function approve(address to, uint256 tokenId) external;
function getApproved(uint256 tokenId) external view returns (address);
function setApprovalForAll(address operator, bool approved) external;
function isApprovedForAll(address owner, address operator) external view returns (bool);

event Transfer(address indexed from, address indexed to, uint256 indexed tokenId);
```

The optional **metadata extension** adds `name()`, `symbol()`, and, most importantly, `tokenURI(tokenId)`.

<Warning>
`setApprovalForAll` gives an operator control over **every** NFT you own in that collection. Marketplaces need it to list your items, but scam sites also ask for it to steal entire collections. Only approve operators you trust.
</Warning>

## Metadata: where the picture lives

Storing images on the blockchain is very expensive, so an NFT usually stores just a **link**. `tokenURI(tokenId)` returns a URL to a JSON **metadata** file:

```json
{
  "name": "Retr0school Graduate #1",
  "description": "Awarded for completing the Web3 track.",
  "image": "ipfs://bafybeigdyrzt5sfp7udm7hu76uh7y26nf3efuylqabf3oclgtqy55fbzdi/1.png",
  "attributes": [
    { "trait_type": "Track", "value": "Web3" },
    { "trait_type": "Level", "value": 5 }
  ]
}
```

Marketplaces and wallets read this JSON to display the name, picture, and traits. The `name`, `description`, `image`, and `attributes` fields follow a widely used convention popularized by OpenSea.

## IPFS: content-addressed storage

If the metadata lives on a normal web server, the owner of that server could change or delete it. **IPFS** (InterPlanetary File System) solves part of this problem:

- Files are identified by a **CID** (content identifier), a hash of their content.
- The same content always has the same CID; changing one pixel gives a new CID.
- So an `ipfs://CID` link always points to exactly that content.

```bash
ipfs://bafybeigdyrzt5sfp7udm7hu76uh7y26nf3efuylqabf3oclgtqy55fbzdi/1.png
```

Browsers do not understand `ipfs://` directly, so apps convert it to a **gateway** URL such as `https://ipfs.io/ipfs/CID/1.png`.

<Note>
IPFS does not keep files alive forever automatically. Someone must **pin** them (keep a copy online). Projects use pinning services or networks like Filecoin or Arweave for long-term storage.
</Note>

## Writing an NFT contract

With OpenZeppelin, a simple NFT collection takes only a few lines:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

contract GraduateBadge is ERC721URIStorage, Ownable {
    uint256 private _nextTokenId;

    constructor() ERC721("Retr0school Graduate", "GRAD") Ownable(msg.sender) {}

    function award(address student, string memory metadataURI)
        external
        onlyOwner
        returns (uint256)
    {
        uint256 tokenId = _nextTokenId++;
        _safeMint(student, tokenId);
        _setTokenURI(tokenId, metadataURI);
        return tokenId;
    }
}
```

- `_safeMint` creates a new token and checks that the receiver can handle NFTs (if it is a contract).
- `_setTokenURI` stores the metadata link for that token.
- `tokenURI(tokenId)` is provided automatically by `ERC721URIStorage`.

<Tip>
For large collections, contracts usually store one **base URI** (like `ipfs://CID/`) and build each token's URI as base URI + token ID, which saves a lot of gas compared to storing every URI.
</Tip>

## Owning an NFT: what it really means

Owning an NFT means the blockchain records your address as the owner of that token ID. It does **not** automatically give you copyright or legal rights to the artwork. Those depend on the project's license terms.

## Summary

- NFTs are unique tokens; ERC-721 tracks who owns each token ID.
- `ownerOf`, `safeTransferFrom`, `approve`, and `setApprovalForAll` are core functions.
- `tokenURI` points to JSON metadata with a name, description, image, and attributes.
- IPFS uses content hashes (CIDs) so links point to exact content, but files must be pinned.
- OpenZeppelin's `ERC721URIStorage` makes building an NFT contract simple.
